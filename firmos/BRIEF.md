# Product Brief

FirmOS — The AI-native operating system for bookkeeping firms. Multi-tenant SaaS for 1-20 person bookkeeping/CAS firms on QuickBooks Online (US). Productizes a validated single-firm practice-management domain model (Yecny Bookkeeping OS) into a per-client-priced ($9–$19/client/mo, unlimited seats) platform. WEDGE (MVP): (1) org onboarding + team invites; (2) client records + accounting-month attribution core library (close tiers 5th/10th/15th, catch-up dates, deferred-until semantics) ported as pure TypeScript with rule tests translated FIRST and gated green before UI; (3) recurring rules materialized into dated work items via Inngest durable functions; (4) Workstation v1 unified daily queue with complete/reopen, reverse-sync to bank-feed/reconciliation/report rows, due-soon/overdue email via Resend; (5) client portal slice: document upload via Vercel Blob signed URLs + waiting-on-you view; (6) client health score (equal-weighted category completion minus overdue penalties) + owner dashboard; (7) Stripe metered billing per active client. OUT OF MVP (later phases): intake quote engine, invoicing-from-actuals, commission payroll, CPA portal, statements module, chat/SMS/push, projects/properties/tax checklists. STACK (ADR direction): Next.js 16 App Router + React 19 + TypeScript on Vercel (single platform, no FastAPI split), Tailwind CSS v4 + shadcn/ui oklch tokens, Neon Postgres serverless driver + Drizzle ORM with org_id RLS multi-tenancy, Inngest durable jobs instead of raw Vercel Cron, Better Auth or Clerk with TOTP MFA, Vercel Blob, Resend, Stripe Billing, Vercel AI SDK 5 agents acting through permissioned server actions with request-to-apply approval workflow, Upstash Redis, Sentry + PostHog HEART metrics. AI layer differentiators: intake copilot, document intelligence (auto-classify/attribute/gap-flag statements and receipts), agent-drafted work items approved by humans feeding on-time metrics, firm-owner copilot over health data.

## EXPERIENCE MANDATE (binding — see docs/DESIGN_MANDATE.md)
The client firm was disappointed in the predecessor build: clunky UI, extreme workflow friction, no color-coding/aesthetic layer for financial work. FirmOS must meet elite-2026 standards: semantic oklch color-coded status system on every surface, <=2 interactions for any daily action, keyboard-first workstation, optimistic UI with skeleton states, glanceable data-dense tables, WCAG-gated accessibility. The StatusBadge semantic token contract is non-negotiable; ad-hoc colors are banned.
